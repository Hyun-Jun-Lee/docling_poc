# 원본 표 캡처와 도구 출력 수동 비교 영역 구현 계획

작성일: 2026-09-11

이 문서는 구현 계획이며, 기능 구현 완료를 의미하지 않는다.

## 목적

PDF·PPTX·DOCX를 한 번에 분석하여 생성하는 하나의 HTML 보고서에서, 사용자가 원본 표 캡처와 Tika·Docling의 추출 결과를 직접 나란히 확인할 수 있게 한다.

하나의 보고서 안에 있는 각 입력 문서의 상세 영역 아래에 수동 비교 공간을 하나씩 배치한다. 문서별로 별도 보고서를 생성하지 않는다.

## 확정된 요구사항

- 원본 표를 캡처한 이미지 파일을 선택할 수 있는 입력을 제공한다.
- 선택한 이미지를 해당 공간에 미리 표시한다. 다른 파일을 선택하면 기존 이미지를 교체한다.
- 이미지 아래에 Tika 출력과 Docling 출력을 복사·붙여넣기 할 수 있는 텍스트 입력 영역을 나란히 배치한다.
- 입력한 공백, 줄바꿈, Markdown·JSON 등의 원문 표기를 보존한다.
- 입력 내용은 현재 열린 페이지에서만 유지한다. 새로고침하거나 페이지를 닫으면 사라진다는 안내를 표시한다.
- 기존 자동 측정 결과와 구간 검토 기능은 유지한다.

## 화면 구성

```text
하나의 HTML 보고서
├─ 전체 측정 결과
├─ 입력 문서 A 상세
│  ├─ 기존 추출 결과 및 검토 영역
│  └─ 원본 표와 추출 결과 수동 비교
│     ├─ 원본 표 캡처 이미지 파일 선택
│     ├─ 선택한 이미지 미리보기
│     └─ Tika 출력 입력란 | Docling 출력 입력란
├─ 입력 문서 B 상세
│  └─ 동일한 구성
└─ 입력 문서 C 상세
   └─ 동일한 구성
```

파일 확장자가 아니라 입력 문서 단위로 구분한다. PDF가 여러 개여도 각각의 상세 영역에 입력 공간이 생긴다. 좁은 화면에서는 두 텍스트 입력란을 세로로 배치한다.

## 제외 범위

- 자동 표 추출, 표 대응, 셀 비교, 정확도 계산
- 붙여넣은 Markdown·JSON·HTML의 해석이나 표 재구성
- 사례 목록, 사례 추가·삭제, 비교 설명 및 판정 입력
- 클립보드 이미지 붙여넣기, 드래그 앤 드롭
- 서버 업로드, 외부 서비스 호출
- HTML 다운로드, JSON 내보내기, 자동 저장, 저장 데이터 복원

여기서 이미지 업로드는 로컬 파일을 브라우저에서 선택해 표시하는 동작이다. 파일을 서버로 전송하지 않는다. 제외 범위는 새 수동 비교 공간에 적용하며, 기존 구간 검토 기능의 JSON 내보내기 등을 제거하지 않는다.

## 코드 수정 계획

### 1. HTML 영역 추가

대상: `src/docling_poc/comparison_report.py`

- 수동 비교 영역을 생성하는 작은 헬퍼 함수 `manual_table_comparison_html()`을 추가한다.
- `generate()`의 문서 반복문에서 기존 `review_html(doc, structures)` 영역 뒤, 해당 문서의 section을 닫기 전에 호출한다.
- 영역별 컨테이너에 전용 클래스 이름을 사용한다.
- 원본 이미지 파일 입력, 이미지 미리보기, 상태 안내, 두 개의 textarea를 생성한다.
- 각 입력에 명확한 label을 연결한다. label로 입력을 감싸는 방식 등을 사용해 문서 간 ID 중복을 피한다.
- 초기 미리보기는 숨기고, 파일이 선택되면 표시한다.
- 기존 선택 실행의 결과를 입력란에 자동으로 채우지 않는다. 사용자가 원하는 구간을 직접 붙여넣는다.

### 2. 레이아웃과 스타일 추가

대상: `src/docling_poc/comparison_report.py`의 CSS

- 스타일을 새 컨테이너 하위로 한정한다.
- 원본 이미지는 비율을 유지하며 컨테이너 너비 안에 표시한다.
- Tika·Docling textarea는 동일한 크기로 나란히 배치하고 크기 조절과 스크롤을 지원한다.
- 원문 비교가 쉽도록 고정폭 글꼴을 사용한다.
- 작은 화면에서는 한 열로 배치한다.

### 3. 이미지 미리보기 동작 추가

대상: `src/docling_poc/comparison_report.py`의 보고서 스크립트 조립 부분

- 간단한 초기화 코드를 `manual_table_comparison_script()` 같은 별도 헬퍼로 분리하고, 기존 고정 script 블록에 합친다.
- 모든 수동 비교 컨테이너를 순회하고 각 컨테이너 내부 요소에만 이벤트를 연결한다.
- PNG·JPEG·WebP 파일을 허용하며 잘못된 형식이나 이미지 디코딩 실패는 해당 영역에 안내한다.
- `URL.createObjectURL()`로 미리보기 주소를 만들고 이미지 교체 시 이전 URL을 해제한다.
- 파일 선택 취소 시 기존 미리보기를 유지한다.
- 빠르게 파일을 교체했을 때 이전 이미지의 로딩 이벤트가 최신 화면을 덮지 않도록 처리한다.
- 붙여넣은 도구 출력은 textarea의 기본 입력 동작으로 처리한다. `innerHTML`을 사용하지 않는다.
- 저장용 상태 모델이나 브라우저 저장소를 추가하지 않는다.

### 4. 수정하지 않는 영역

- `src/docling_poc/comparison_data.py`: 비교 지표·스냅샷 로직 유지
- 벤치마크 실행부 및 Docling·Tika 변환 설정: 유지
- `comparison_review.py`, `comparison_review.js`, `comparison_structure.py`: 기존 구간 검토 기능 유지
- `analysis.json`, `manifest.json` 및 검토 JSON 스키마: 유지

이번 기능은 작으므로 별도 Python·JavaScript 모듈을 새로 만들지 않고 보고서 생성 파일의 작은 헬퍼들로 구성한다.

### 5. 사용 안내 보완

대상: `docs/comparison-guide.md`

- 각 문서 상세 영역에서 원본 표 이미지 파일을 선택하는 방법을 설명한다.
- Tika·Docling 출력의 필요한 구간을 원문 그대로 복사·붙여넣도록 안내한다.
- 파일은 외부로 전송되지 않으며 입력 내용은 저장되지 않는다고 명시한다.

## 구현 순서

1. 수동 비교 HTML 헬퍼와 문서별 삽입 위치 추가
2. 이미지·텍스트 입력 레이아웃 추가
3. 이미지 선택·교체·오류 처리 연결
4. 회귀 테스트와 브라우저 동작 확인
5. 사용 가이드 갱신

## 검증 계획

### 자동 검사

`tests/test_comparison.py`에 필요한 회귀 테스트를 추가한다.

- 여러 입력 문서가 있는 보고서에 문서 수만큼 독립적인 수동 비교 영역이 생성되는지 확인한다.
- 기존 시간 요약, Markdown 원문·스타일 전환, 구간 검토 영역이 유지되는지 확인한다.
- 일반 HTML과 `--standalone` 결과에 새 영역과 초기화 스크립트가 포함되는지 확인한다.
- 기존 문서 내용 이스케이프 검증을 유지한다.

구현 후 관련 pytest와 Ruff를 실행한다. 자동 테스트만으로 이미지 입력 동작을 검증했다고 판단하지 않는다.

### 브라우저 확인

별도 임시 출력 경로에 생성한 보고서로 확인하며 기존 샘플 결과를 덮어쓰지 않는다.

- 이미지 파일 선택, 미리보기, 다른 이미지로 교체가 정상 동작한다.
- 잘못된 파일·손상된 이미지에 오류 안내가 나타나고 정상 이미지로 재시도할 수 있다.
- 한 문서의 이미지 선택이나 텍스트 입력이 다른 문서 영역에 영향을 주지 않는다.
- 한글, 공백, 줄바꿈, Markdown, JSON을 붙여넣었을 때 원문 표기가 유지된다.
- `<script>` 등의 문자열이 실행되지 않고 입력 내용으로 남는다.
- 좁은 화면에서도 이미지와 두 입력란을 사용할 수 있다.
- 로컬 HTML에서 외부 통신 없이 동작한다.
- 새로고침하면 입력이 초기화되고, 입력 공간에 이 동작을 설명하는 안내가 있다.
- 기존 보고서 기능이 정상 동작한다.

## 완료 기준

하나의 HTML 보고서에 포함된 각 입력 문서의 상세 영역에서 원본 표 이미지를 선택해 보고, 그 아래에 Tika·Docling 출력을 직접 붙여넣어 나란히 확인할 수 있다. 자동 분석이나 저장 기능을 추가하지 않고 기존 측정 및 검토 동작을 유지한다.
