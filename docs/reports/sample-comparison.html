ETL과 ELT 

ETL 

데이터를 수집(E)한 후 변환 작업(T)을 먼저 수행한 다음 저장(L)하는 데이터 처리 과정 

변환 과정을 통해 고품질의 데이터를 저장하여 바로 분석 가능. 

데이터 변환 과정에서 시간이 오래 걸릴 수 있으며 변환을 위한 인프라와 리소스가 많이 필요함. 

데이터 마트 구축, 일일 보고서 생성, 웹 로그 데이터 분석 등에 유용. 

ELT 

데이터를 수집(E)한 후 변환 없이 먼저 저장소에 저장(L)한 후 변환 작업(T)을 수행하는 데이터 처리 과정 

데이터를 저장한 후 다양한 변환 작업을 적용할 수 있어 유연함. 

초기 데이터 적재 속도가 매우 빠르지만 적재된 데이터 품질이 낮고 활용성이 떨어질 수 있음.

ETL과 ELT

ETL

데이터를 수집(E)한 후 변환 작업(T)을 먼저 수행한 다음 저장(L)하는 데이터 처리 과정

변환 과정을 통해 고품질의 데이터를 저장하여 바로 분석 가능.

데이터 변환 과정에서 시간이 오래 걸릴 수 있으며 변환을 위한 인프라와 리소스가 많이 필요함.

데이터 마트 구축, 일일 보고서 생성, 웹 로그 데이터 분석 등에 유용.

ELT

데이터를 수집(E)한 후 변환 없이 먼저 저장소에 저장(L)한 후 변환 작업(T)을 수행하는 데이터 처리 과정

데이터를 저장한 후 다양한 변환 작업을 적용할 수 있어 유연함.

초기 데이터 적재 속도가 매우 빠르지만 적재된 데이터 품질이 낮고 활용성이 떨어질 수 있음.

저장소 리소스 낭비와 비용 증가의 가능성 있음.

빅 데이터 분석, 실시간 데이터 스트리밍 처리, 클라우드 데이터 레이크 관리, IoT 데이터 처리에 적합.

## ETL ©

- 데이터를 수집(E)한 후 변환 작업(T)을 먼저 수행한 다음 저장(L)하는 데이터 처리 과정 ㅇ

## ELT 개

- 데이터를 수집(E)한 후 변환 없이 먼저 저장소에 저장(L)한 후 변환 작업(T)을 수행하는 데이터 처리 과정 ㅇ
- 데이터를 저장한 후 다양한 변환 작업을 적용할 수 있어 유연함.
- 초기 데이터 적재 속도가 매우 빠르지만 적재된 데이터 품질이 낮고 활용성이 떨어질 수 있음.

ETL과 ELT

ETL ©

  • 데이터를 수집(E)한 후 변환 작업(T)을 먼저 수행한 다음 저장(L)하는 데이터 처리 과정 ㅇ
  • 변환 과정을 통해 고품질의 데이터를 저장하여 바로 분석 가능.
  • 데이터 변환 과정에서 시간이 오래 걸릴 수 있으며 변환을 위한 인프라와 리소스가 많이 필요함. o
  • 데이터 마트 구축, 일일 보고서 생성, 웹 로그 데이터 분석 등에 유용.

ELT 개

  • 데이터를 수집(E)한 후 변환 없이 먼저 저장소에 저장(L)한 후 변환 작업(T)을 수행하는 데이터 처리 과정 ㅇ
  • 데이터를 저장한 후 다양한 변환 작업을 적용할 수 있어 유연함.
  • 초기 데이터 적재 속도가 매우 빠르지만 적재된 데이터 품질이 낮고 활용성이 떨어질 수 있음.
  • 저장소 리소스 낭비와 비용 증가의 가능성 있음. ㅇ
  • 빅 데이터 분석, 실시간 데이터 스트리밍 처리, 클라우드 데이터 레이크 관리, IoT 데이터 처리에 적합.

Batch & Streaming

  • Batch : 많은 양의 데이터를 정해진 시간(매시, 매일, 매월, 매년 등)에 일괄적으로 처리하는 것 ㆍ

Orchestration 도구 활용의 필요성

1. 데이터 복잡성과 볼륨 증가

  • 빅데이터 시대의 도래로 정형, 비정형 데이터들의 복잡성 및 볼륨 증가 ㅇ

2. 다양한 파이프라인 환경 관리

  • 분산 처리 도구, 클라우드 등 다양한 IT 기술 등장으로 데이터 관리 파이프라인이 복잡·다양화 ㅇ

3. 복잡한 워크플로우 효율적 제어

  • 여러개의 작업이 연결되고, 동시에 수행되는 복잡한 파이프라인 작업에 대한 효율적인 관리 필요

4. 자동화·스케줄링·모니터링 통합

  • 다수의 작업을 각기 다른 배치 간격으로 스케줄링하고 이를 통합적으로 모니터링 할 수 있도록 함

5. 안정적인 에러 처리와 재실행

  • 작업 간에 에러 발생시, 에러 추적과 재수행을 용이하게 할 수 있도록 함 >

  • 웹 기반 UI 제공 ©
  • Airflow UI를 통해 실행 현황 및 작업 상태에 대한 실시간 정보를 직관적으로 파악 가능 o
  • 다양한 실행 환경
  • Local, Sequential , Kubernetes, Celery 등 인프라 상황에 맞게 다양한 실행 환경에서 구동 가능 ©
  • 데이터 소스 및 서비스들과의 통합 ( 👉 providers list ) * ㆍ
  • 80개 이상의 연결 가능한 서비스와 1000개 이상의 오퍼레이터를 제공하여 거의 모든 데이터 관련 작업이 가능 ©
  • 강력한 스케줄링 기능
  • Cron 표현식, 백필(Backfill), 캐치업(Catchup) 등 다양한 스케줄링 옵션을 제공하여 유연한 작업 실행을 지원 ㅇ

DAG (Directed Acyclic Graph)

  • '유향 비순환 그래프' 라는 뜻으로, 자신으로 되돌아오는 경로가 없는 그래프.
  • 파이프라인 작업은 하나의 작업이 다른 작업에 의존하거나 특정 순서로 실행되어야 하기 때문에 방향성을 가진다. *
  • 작업의 실행 순서 보장과 무한 루프 방지 등을 위해 완료된 작업을 다시 호출할 수 없도록 강제한다.
  • Airflow에서 하나의 온전한 파이프라인 작업 스크립트를 Dag라고 칭한다. ㆍ
